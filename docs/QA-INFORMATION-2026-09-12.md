# 信息传递与在场修复验收

日期：2026-09-12。范围：Web 版的信息传递、同场在场、地点获知、结算恢复与存读档。对应概念基线 v0.12、存储格式 17。

## 已修复问题

- 同场直接传入完整消息，使旁观者看到耳语、纸条与人物心声；改为冻结实际在场者，编译并保存逐人可观察的原文片段。规划、正文、裁判和恢复使用同一投影。
- 部分观察获知被扩大为整件事件；认知层现在只传递来源中实际获知的版本，保留转述归属、误解和信念，不附送正史的详情、地点或时间。
- 房间历史名单被当成当前在场，私人入场、离场与转场互相覆盖；新增独立在场身份，陈旧入口不能生成，转场只移动当前发言者和玩家，不把房间其他成员带走。
- 同场私有线索、情绪与身体状态写入共享现场；改为个人连续性。未听见最新输入的角色不会回退到旧问题。
- 已登记地点无法经玩家转告给另一角色复用；现在保存带来源的地点认知并复用唯一 ID，只知名称不等于拥有路线或通行权限。
- 玩家只提及地点别名，却让接收者同时获得登记的正式名称；地点个人版本改为保留实际所闻称呼，不以 ID 相同扩大所知信息。
- 后续排队回复重复旧位置、时刻或玩家痕迹，可能回写已经变化的状态；剔除相对原轮快照没有变化的字段，旧事件时间仍按发生时刻保留。
- 旧同场来源、摘要、脉搏和存档存在再次扩大可见范围的入口；统一经过来源投影，格式 16 的检查点升级包含观察、个人现场和在场身份。
- 提案修复只提供报错而丢弃原提案；现在携带原始 source_id 提案与具体问题，修复后仍执行完整校验，不放宽接受标准。

具体契约与各模块入口见 [INFORMATION-FLOW.md](INFORMATION-FLOW.md)。

## 回归验证

使用独立临时数据库覆盖：创建世界、私人入场、同场发送与角色回应、逐人观察、部分事件获知、关系与地点写回、跨角色转告、脉搏认知、陈旧入口、转场、恢复队列、存档迁移及读档。

同场秘密案例贯穿规划、正文、裁判和语义核对；检查实际模型请求没有包含旁观者未听见的内容。恢复旧知识也按观察限缩，合法公开传播继续可用。

Python 全量回归与现有前端 Node 回归均通过（`python -m unittest discover -s tests -v`、`node --test tests/frontend_review.cjs`），`git diff --check` 通过。没有新增浏览器视觉验收，也没有测试 iOS；本轮不修改前端表现。

## 真实 DeepSeek 验证

使用 `deepseek-v4-flash`，在服务器独立目录和新数据库测试。模型配置只读复用；未向线上玩家世界发送消息。

同场观察两例首次通过：

- 玩家向洛恩耳语“青铜海鸥”，同时公开询问喝茶。伊芙琳只获得公开茶话，耗时 2.01 秒。
- 洛恩递纸、纸内秘密、人物心声与公开茶话混合。伊芙琳只获得可见递纸动作和公开话语，未获得纸条内容或心声，耗时 7.51 秒。

地点测试保留了修复前失败：自然新地点登记成功，但跨角色转告先后因普通问话进入 active_threads、关系缺证据和转述归属问题整轮拒绝。没有把拒绝当成写入成功。

加入原提案定向修复后，在同一个干净测试世界连续发送三条消息：

| 输入 | 结果 | 耗时 |
| --- | --- | --- |
| 向洛恩转述“外廊值守室”名称 | 修复后接受，保存玩家转述版本 | 61.72 秒 |
| 预约入口见面 | 发布前校验失败，本轮正文未发布、未移动 | 123.67 秒 |
| 先记住名字，以后再说 | 修复后接受，队列无残留 | 63.88 秒 |

预约规划使用同一地点 ID，地点总数保持 7，没有重复创建或提前抵达。洛恩的上下文不含登记者独有外观“三角形蓝瓷钉”；未被告知的伊芙琳没有获得该地点。真实请求中的 4 次定向修复均携带与上一份输出完全一致的原始提案和具体问题。

预约最终仍失败：模型删除关系数值变化后，保留变更后的关系说明却再次漏填关系证据。确定性校验拦下了它。此次验证证明了地点复用与信息边界成立，不能据此宣称真实模型每轮都能成功结算；多次校对也有明显等待成本。

原始诊断保存在忽略版本控制的 `data/diagnostics/information-live/`，包括失败报告；其中不保存模型密钥。
