# 整体检查与修复 · 2026-09-08

检查范围：世界创建与输入校验、模型连接和流式生命周期、私人对话与多人房间、结算恢复、世界推进、上下文与历史、前端故障恢复、本地密钥保存。遵循当前单一正史设计；历史分支入口不重新开放。

## 修复

- 流式连接正常结束但缺少模型完成信号时，原先可能将半截正文当作完成回复。现在保留错误正文，不结算，也不作为后续有效上下文；取消生成同时关闭提供方连接并释放世界锁。
- 缺少有效模型配置时，先校验连接配置再记录玩家消息，避免私聊和房间留下未实际发送的消息。Anthropic 的输出用量增量不再覆盖输入与缓存用量；连接测试使用直接输出。
- 普通回合、房间和页面现场采用共享世界时钟，避免切换场景后回退时间。上一场结算快照独立保留为历史参考；明确清空的身体与情绪字段能正确落库。
- 新时段入场使用独立提示词、当前状态和标为历史的原上下文，约束重问已答问题及重演旧选择。删除过时话题与兑现明确承诺分开校对，避免旧话题无法清理。
- 时间不一致与 JSON 解析失败会将具体错误反馈给重试提取，避免盲目重复相同请求。结算失败后的原有暂停、保留正文和按序恢复规则保持不变。
- 世界推进用保留/清除操作及痕迹索引选择已有玩家状态，避免模型重写原文触发误拒绝。角色重新变为可接触也能成为有效变化来源。空世界禁止推进的现有规则保留。
- 前端房间在断线且最终历史刷新失败时，仍会恢复输入并停止书写指示；修复异地角色显示“就在眼前”、请求头合并及输入校验错误呈现。
- 输入去除首尾空白后校验，拒绝空名称和未知协议。密钥文件采用原子替换；损坏文件不会被当作空配置覆盖，页面仍可打开。

- Python 全量回归 54 项，覆盖创建、进入、流式回复、状态落库、结算重试与世界推进等关键路径。
- Node 前端回归 4 项：请求与错误、跨字节流解码、房间故障恢复、角色可接触性；另检查 JavaScript 语法与差异空白。
- 隔离数据库的真实浏览器验证：书架到世界到私聊、往返草稿保留、创建多人房间、无模型配置发送失败后无多余消息且草稿保留、输入恢复。
- 使用现有 DeepSeek 对原失败回合重新提取并独立校对，第二次尝试通过领域与语义检查，保留明确承诺并移除过时酒会准备话题。该验证只检查提案，没有写入个人世界。

## 仍有的限制

提示词与独立校对不能保证彻底消除模型虚构背景细节。自然语言故事时间的先后仍依赖模型理解；严格字段校验及持久化失败队列继续保留，遇到无法通过的提案会暂停推进，不绕过检查写入正史。
