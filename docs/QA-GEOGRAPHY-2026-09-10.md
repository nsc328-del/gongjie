# 地点扩展与后台结算实测 · 2026-09-10

## 线上原始故障

只读检查 owner 空间后确认：塞维安的“走吧”回合描写了未登记的“外围检修通道”，地点校验拒绝整轮，后续正文继续沿用该场景，结构化位置却仍在内阁书库。结算另有两类故障：网页断开会取消已保存正文的结算；DeepSeek 思考输出耗尽额度时可能返回空正文，旧路径误当成无效提案。

## 实现

- 每轮生成前区分原地细节、仅提及地点、需要确认目的地。问路、预约和出发使用同一场景规划契约。
- 程序检查字段、原文来源、世界/父级归属、既有名称/别名和重复；模型独立检查世界设定及权限。普通新地点可归属世界根区域，简单世界书不需要先列全地图。
- 目的地正文及完整状态提案先核对，再展示。问路确认地点不移动，出发且正文抵达才改变位置；入门位置不授予锁内权限。
- 地点、知情来源、位置和结算同一事务落库。其他角色的输入与世界推进只获得其可知地点；私有重复地点在正文发布前被拦截，不泄露其描述。
- 新地理随存读档保存，旧检查点迁移；重置清理游玩新增地点，保留创作底稿明确引用的地点。
- 正文保存后后台队列接管；刷新不取消，人工重试加入同一个任务。进程中断保留可恢复任务，前端观察处理结果并保留草稿。
- 模型截断作为提供方未完成处理，核对采用独立输出额度。证据缺失返回具体字段，修复不能靠猜测遗漏项。

使用线上 owner 的只读 SQLite 备份，在服务器独立测试目录调用真实 `deepseek-v4-flash`；未在玩家正史中推进测试剧情，也未输出密钥。

目的地回合的完整发布耗时约 72–149 秒，包括设定核对、正文核对及完整结算；有一次自动修正。普通窗边回合约 8 秒。核对仍依赖模型语义能力，不能保证所有世界设定冲突均被识别。

本地实际浏览器验证：发送 → 正文完成而结算受控等待 → 刷新 → 重进角色 → 输入草稿 → 放行后台任务。处理标记自动消失，右栏更新，发送解除禁用，草稿保留。没有“继续生成”的假光标，也没有让刷新后的用户重复启动正在运行的结算。

自动回归覆盖：确认与抵达分离、同场成员转场、知情隔离、受限字段和来源、跨世界归属、隐蔽重名、事务故障无半地点、恢复幂等、检查点迁移、存读档/重置、断线后后台队列继续及提供方截断。前端既有关键交互回归通过。
