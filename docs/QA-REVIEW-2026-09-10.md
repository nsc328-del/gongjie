# 共界 Web 整体复查 · 2026-09-10

本轮以创建世界、进入角色、流式回复、状态结算、时间预告与推进、存读档为主线，复查密码空间隔离与多人同场。iOS 仍暂停，本轮没有改动或验证原生版。

## 已修复

| 优先级 | 问题与触发方式 | 处理 |
| --- | --- | --- |
| P1 | 模型把证据 kind/role 或事件 visibility 返回为数组，领域校验抛 TypeError，绕过有限修复与拒绝终结，使回合一直待记录。 | 先验证字段类型。无效提案按原轮重提，仍无效则 rejected；基础设施故障仍保留待结算。 |
| P1 | 点击“继续写”时，裁判仍能引用上次玩家台词，重新形成玩家承诺或同意。 | 冻结 continuation 标志；继续写无新玩家证据。普通私人回合只取尚未被回应的末尾玩家消息，同场各角色仍共用当前轮玩家输入。 |
| P1 | 拒绝标记使用未过滤的历史序号，入场却只取最近六条；入场校对还丢掉拒绝状态。 | 过滤与裁剪后关联元数据，校对及提取保留 outcome；拒绝的旧主张不能重新成为事实基线，历史正文不插入系统说明。 |
| P2 | 回合、切换现场或读档发生后，旧预告请求可能覆盖新预告；同场显示规划中却没有发请求。 | 前端按世界记录请求版本，忽略过期结果及错误；同场启动预告。失效后允许重新规划。预告更新只改聊天区外的预告节点，保留输入框。 |
| P2 | 规划返回现实钟点或过长文本时，可先作为预告显示，点击后才失败。 | 保存预告前执行与世界推进一致的时间底线校验，不发布不可执行的时刻。自然语言先后仍依赖规划模型。 |
| P2 | 进入角色/同场用局部 player 覆盖世界 player，丢失 ready_to_visit；读档前的慢刷新可能覆盖读档结果。 | 入场后读取完整世界数据；世界导航淘汰旧刷新，对话刷新校验导航版本。 |
| P2 | 存档弹窗允许多个保存/读取请求交叉；读档漏清同场草稿；手机隐藏左侧栏后无法打开存档。 | 同一弹窗串行处理操作，加载清理同场草稿；手机视角抽屉增加存读档入口。 |
| P2 | 同场发送前等待服务器确认，消息短暂消失。 | 提交时立即显示本地消息，收到确认后替换；未确认失败恢复草稿。 |
| P2 | 已互动或推进过的角色卡仍可能展示最初“授权书尚未签署”等相遇文案。 | 不再把沿用的初始相遇牵引作为当前描述；新时段未见过的角色同样使用当前状态。 |

## 验证

- 新增回归先在修改前复现了异常字段、继续写复用旧证据、拒绝状态序号错位，再确认修复。
- Python 全套通过，覆盖事实/认知边界、结算恢复及幂等、同场、角色连续性、预告消费与失效、完整读档与世界/密码空间隔离。
- 前端回归覆盖慢请求、过期预告、输入保留、即时发送、完整正文覆盖、存档重复点击与草稿清理。
- 在独立临时数据库、固定模型响应的本地服务上，通过实际浏览器验证首次入场、发送与回复结束、预告生成、推进到预告时刻、读档回到推进前，以及自动备份保留。390×844 布局下实际打开存读档，检查列表与按钮。
- 线上 owner 与 test 数据库 quick_check 均通过，发布前均无待结算任务。本轮不推进或改写线上剧情。

## 保留的边界

这次验证的是系统行为，不是新一轮 DeepSeek 长篇剧情质量评测。自然语言日期比较、证据语义支持与叙事创作仍有模型判断环节，不能保证绝无编造或误判；已拒绝叙事与已确认事实仍明确分层。

动态地点创建继续保留在 TODO。没有修改按钮文案、余波展示规则、跨回合断句理解或角色卡设定。没有提交整个已有工作区的累积改动。
