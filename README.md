# 共界

多角色共享世界的本地沉浸式角色扮演原型。

## 启动

```bash
./start.sh
```

打开 <http://127.0.0.1:8768>，在右上角连接 OpenAI-compatible 或 Anthropic Messages API。

## 当前闭环

- 从世界书架进入一个持续世界：先看见此刻的公开局面，再从依次浮现的角色卡中选择要去见的人。
- 角色首次进入时根据当前有效的世界局面、相遇牵引与自己的认知生成一次开场，经记忆校对后保存；不会在次日重演最初的夜晚。
- 每名角色拥有独立人格、欲望指纹、关系与知识边界。
- 回复后由独立状态裁判提取场景、关系、事件与知情范围；硬变化附原文和知情来源，经语义核对与领域校验后自动写入世界。
- 结算失败保留正文和待记录状态，刷新后可“重新记录”；按原顺序恢复成功前暂停该世界的新回合与时间推进，草稿仍可编辑。
- 角色只获得自己所知的事实或信念，误解不携带客观答案，他人的实时位置不自动进入私聊上下文。
- 亲历者立即获得认知；公开变化会在世界脉搏后分别进入其他角色的认知投影，私密与秘密不会自动扩散。
- 返回世界只是暂离现场；玩家可以继续接触其他角色，再主动推动世界脉搏，让下一时段自然展开。
- 世界进入新时段后，第一次重新进入某名可接触角色时会生成一次接续开场；同一时段重复进入不会重写，角色默认安静；每次相遇均携带完整的人物底色，历史会标出再次相遇。
- 待履行承诺保留稳定记录，明确赴约后移除；世界页可直接进入承诺对应的人物现场，点击本身不算兑现。
- 时间推进拒绝无效锚点，不替玩家补写路线或经历；不在场者看不到玩家实时位置和痕迹。
- 角色回复下方会显示轻量的世界记录，世界驾驶舱只展示公开大事与角色表层状态。
- API Key 独立保存在 `data/secrets.json`，不进入 SQLite 或 Git。

Provider 层沿用了 Aru `codex/full-shell-material-recipes` 分支的核心边界：provider-neutral request context、协议 adapter、SSE canonical event、cumulative stream snapshot 与 normalized error。

## 开发入口

- 产品语义与模块边界以 [`docs/CONCEPT.md`](docs/CONCEPT.md) 为准。
- 后端入口是 `gongjie.app:app`，前端仍由 `static/` 提供。
- 关键验证运行 `.venv/bin/python -m unittest discover -s tests -v`。

DeepSeek V4 的交互生成使用直接输出，语义核对与记忆校对使用 low 思考强度，避免默认高强度思考耗尽输出预算。参数映射依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)，其他模型按现有协议处理。
